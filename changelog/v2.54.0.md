### 📈 Skor bertingkat (metrik 1, 2, 3, 14) & nilai bulanan metrik OUTCOME (Added / Changed)

- **Permintaan user**: (1) metrik 14 "% employees receiving recognition / year" dinilai per tier jumlah penerima (tier 1 < 4000, 2: 4000-4999, 3: 5000-5999, 4: 6000-7499, 5: >= 7500), persen = nilai / batas bawah tier x skor tier / 5 x 100% (6400 -> 6400 / 6000 x 4 = 4.27 -> 85.33%), nilai default 6400; keputusan user: tier 1 proporsional terhadap 4000, maksimum 100%. (2) Metrik OUTCOME mendapat Template + Upload + Evidence: satu nilai bankwide per bulan (Year | Month | Value | Notes); YTD memakai nilai bulan terakhir; setiap metrik menampilkan "Last update" (periode data terakhir). (3) Perlakuan tier yang sama untuk metrik 1 (disebut user "Social Media Engagement Rate"; nama metrik tidak diubah; tier <= 1% / > 1% / > 2% / > 2.5% / > 3.5%, target 2%, nilai 0.66% per September 2026) dan metrik 3 "Success ratio candidate from targeted university" (tier < 30% / >= 30% / >= 45% / >= 60% / > 75%, target > 70%, nilai 75.04% per September 2026). Setiap metrik N/A tidak ikut PX Index.
- **Skor bertingkat**: kolom baru `px_metrics.score_tiers` (`NVARCHAR(400)`, JSON `{ "unit": "percent"|"number", "bounds": [{ "min", "op": ">="|">" }] x 4 | null }`; `bounds` = batas bawah tier 2..5, `op` menentukan apakah batas itu sendiri sudah masuk tier atas). `NULL` = dinilai menurut `scale_type` seperti sebelumnya; `bounds: null` = tier belum diatur (N/A). Logika bersama di `server/db/scoreTiers.js` (`parseTierConfig`, `readTierConfig`, `resolveTierConfig`, `tieredScore`) dan `src/utils/scoreTiers.js` (UI). Rumus: tier 1 = nilai / batas tier 2 x 1; tier t (2..5) = nilai / batas bawah tier t x t; persen = skor / 5 x 100, dibatasi 0..100. `normalizeScore`/`normalizeTarget` (`calculationEngine.js`) memakai tier, jadi scorecard, Performance Trend, PX Index per direktorat, dan alert konsisten.
- **N/A**: metrik bertier dengan `bounds: null` -> `status: NO_DATA` + `not_applicable: true`, nilai/skor `null`, `target_value_normalized` `null`; tidak ikut Survey/Outcome/PX Index, rollup journey, alert, maupun trend. UI menampilkan "N/A".
- **Nilai bulanan OUTCOME** (`server/services/outcomeValueService.js`; tabel baru `px_outcome_values` (unik metrik+tahun+bulan, `DECIMAL(18,4)` >= 0, `source` `UPLOAD`|`SEED`) dan `px_outcome_uploads`; JSON `outcomeValues`/`outcomeUploads`): berlaku untuk semua metrik OUTCOME kecuali metrik 11 (dihitung dari absensi event); metrik 1 juga (nilainya; upload social media v2.52.0 tetap sebagai drilldown). Upload `.xlsx` (maks. 5 MB) divalidasi utuh - satu error -> tidak ada yang disimpan, semua error dilaporkan per baris/kolom; upsert per metrik+bulan; bulan setelah bulan berjalan ditolak; file asli disimpan di `server/data/outcome-uploads/` (gitignored).
