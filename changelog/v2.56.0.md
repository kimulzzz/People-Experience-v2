# [2.56.0] - 2026-10-23

### 📜 Tab History di detail metrik = data di balik tombol Evidence (Added / Changed)

- **Permintaan user**: data yang ada di file Evidence setiap metrik juga harus tampil di detail metrik; tab "Internal Transaction Records" diganti nama menjadi **History** agar familiar bagi user.
- **Endpoint baru `GET /api/metrics/:id/history`** (login wajib): periode `?period=YTD|YYYY|YYYY-MM|ALL` (sama dengan evidence) atau `?mode=&year=&month=` (sama dengan detail); `?directorate=` / `?sub_directorate=` hanya untuk cek cakupan USER (di luar cakupan 403). Respons `{ metric_id, kind, period, columns: [{ key, label, hidden? }], rows, total, identity_hidden, scope_limited, reason }`, baris terbaru dulu. Tanpa login 401, id bukan angka 400, metrik tidak ada 404, periode salah 400.
- **Satu sumber data**: builder evidence kini membuat baris dulu, baru CSV (`outcomeEvidenceTable`, `partEvidenceTable`, `essEvidenceTables`, `generateSurveyEvidence({ tablesOnly: true })`); `server/services/metricHistoryService.js` (baru) memakai fungsi yang sama, jadi isi tab History dan file Evidence tidak bisa berbeda. Kunci kolom = header CSV evidence; `Metric_ID`, `Metric_Name`, `Upload_ID`, `File_SHA256`, `Updated_At` tetap ada di baris tetapi disembunyikan di UI (`hidden: true`). Menurut laporan developer, unduhan Evidence byte-identik dengan v2.55.1 untuk 27 metrik (periode 2026, 2026-09, 2025).
- **Jenis History (`kind`)**:

  | `kind` | Metrik | Isi |
  | :--- | :--- | :--- |
  | `NOT_AVAILABLE` | 4, 6, 8, 10, 23, 26 (`data_status` `NOT_AVAILABLE`) | kosong + `reason` (Evidence tetap bisa diunduh) |
  | `PARTS` | 5, 7, 12, 19, 20 | baris semua bagian dalam satu tabel (kolom Part); metrik 12 per event/pertanyaan |
  | `ESS` | metrik ESS | semua periode, seperti evidence ESS |
  | `SURVEY_RESPONSES` | survei SYSTEM | satu baris per responden |
  | `EVENT_ATTENDANCE` | 11 | absensi event periode itu |
  | `OUTCOME_VALUES` | OUTCOME dengan nilai bulanan tersimpan (1, 3, 14) | nilai per bulan; metrik `AVERAGE` (1, 3) dengan baris "Average" per tahun |
  | `OPERATIONAL` | OUTCOME tanpa nilai bulanan | records operasional detail (tidak ada metrik live saat ini) |

- **UI**: setiap metrik punya tab **History (n)**; label "Internal Transaction Records" dan "Respondent Records & Answers" dihapus. `src/components/MetricHistoryTable.jsx` (baru): cari di semua kolom, 50 baris per halaman, "Showing X-Y of Z". Survei SYSTEM tetap memakai tabel responden lama (kini berjudul History); tabel absensi metrik 11 diganti tabel bersama; metrik ringkasan tetap membuka tab "Summary Parts" lebih dulu. 403 -> "No access to the history of this metric."
- **Akses** (tidak lebih luas dari sebelumnya; siapa pun yang bisa membuka detail mendapat History):
  - Admin: semua baris termasuk identitas, tidak dipersempit filter direktorat Dashboard (sama seperti unduhan Evidence; tab menyebutkannya).
  - PIC metrik SURVEY: identitas responden, hanya baris di cakupan sendiri (metrik karyawan).
  - USER: survei SYSTEM tanpa kolom identitas, baris cakupan sendiri (metrik 2 non-karyawan: semua baris tanpa identitas); metrik 11 tanpa NIP/nama/e-mail dan hanya direktorat sendiri; baris ESS/bagian hanya direktorat sendiri, tanpa baris Bankwide (metrik 5 non-karyawan: semua baris); nilai bulanan OUTCOME apa adanya.
  - Unduhan Evidence tetap hanya Admin/PIC.
- **Tes**: Modul 61 (9 tes, 2 khusus SQL) -> suite penuh SQL **385/385 lulus, 0 gagal, 16 dilewati** (`TEST_SKIP_MODULES=8,24,27,32,38,41,42,43`). Suite JSON penuh tidak dijalankan. Ukuran suite = **471** menurut hitungan (`await runTest(` statis 458 + selisih 13 yang sama sejak v2.30.2).

- **Catatan**: angka (n) di tab History survei SYSTEM berasal dari daftar responden detail yang dibatasi 100 baris; modal selalu mengambil History saat dibuka (satu request tambahan kecil). Tidak ada tabel, setting atau env baru.
