# [2.43.0] - 2026-10-20

- **Laporan user**: akun `rt37adminmvg452zw` sudah tidak ada di Manage Users tetapi Audit Trail tidak menunjukkan akun itu dihapus. Penyebab: akun itu admin sementara regression test (Modul 37); suite (dan skrip verifikasi/QC) membuat dan menghapus akun langsung lewat `storage.createUser/deleteUser`, bukan lewat API, jadi tidak ada baris USER_CREATE/USER_DELETE - tetapi aktivitas akun tes itu di API (login, membuat user tes, reset password, upload) tetap diaudit. Akibatnya 9.521 dari 9.791 baris `px_audit_log` adalah sampah tes. Keputusan user: entri tes tidak perlu ditampilkan di Audit Trail. Data audit TIDAK dihapus (kepatuhan), hanya ditandai.
- **Skema**: `px_users.is_test_account BIT NOT NULL DEFAULT 0` dan `px_audit_log.is_test BIT NOT NULL DEFAULT 0` (CREATE TABLE + ALTER idempoten saat boot; JSON `auth.json`: field yang sama, kosong = false).
- **Pengenalan akun tes (server-side saja)**: flag hanya bisa dipasang oleh kode server lewat `storage.createUser({..., is_test_account: true})`; `updateUser` dan `POST/PUT /api/admin/users` tidak menerimanya dari body/header/query (dites). Akun yang dibuat lewat API mewarisi flag admin pembuatnya. `authService.audit()` menandai `is_test` bila akun pelaku ATAU akun yang dikenai aksi (opsi baru `subject` pada create/update/scope/reset/delete) adalah akun tes - selalu dari data DB, tidak pernah dari request. Login gagal untuk username yang tidak terdaftar tidak pernah ditandai (informasi keamanan).
- **Penandaan data lama** (`markHistoricalTestAudit()`, sekali pada boot yang menambah kolom, idempoten; aturan nama di `server/db/testAccounts.js`): akun yang masih ada memakai flag-nya (`admin` tidak pernah ditandai); akun yang sudah dihapus hanya bila namanya pola tes: `rt-suite-*`, `qc-*`, `verify-*`, atau `rt` + token + stamp 8 karakter (2026+). Hasil di DB utama: **9.525 baris ditandai, 266 tetap tampil** (237 login gagal username tak dikenal, 12 baris `admin`, 1 skrip impor exit interview, 16 baris akun dev/verifikasi lama `probe-*`, `snap-*`, `devadmin`, `dev-admin` yang di luar pola - dibiarkan tampil).
- **API**: `GET /api/admin/audit-log` default tanpa baris `is_test`; `?include_test=1` menyertakannya; setiap baris kini membawa `is_test`; limit diterapkan setelah filter.
- **UI** (`UserManagementModal.jsx`, Admin Parameters -> Manage Users -> Audit Trail): kotak centang "Show test-run entries" (default mati) + badge abu-abu "TEST".
- **Tes**: semua `storage.createUser` di `tests/regressionTest.js` memakai `is_test_account: true`; 9 pembacaan audit yang mencari aktivitas tes memakai `include_test=1`. Modul 48 baru (7 tes: aturan nama; via API - akun buatan admin tes = akun tes, disembunyikan default, terlihat dengan include_test, flag tidak bisa diubah klien, audit butuh sesi, limit setelah filter; SQL-only app sementara - aksi admin asli tetap tampil, reset password akun tes oleh admin asli ditandai, login gagal username tak dikenal tidak ditandai, penandaan ulang = 0). Suite penuh SQL (developer, backend kedua): **237/237 lulus, 0 gagal, 16 dilewati** (`TEST_SKIP_MODULES=8,24,27,32,38,41,42,43`); JSON hanya 4 cek in-process. Satu run suite kini menyisakan 5 baris tampil (login gagal username tak dikenal). Dicek main session di browser: Audit Trail default tanpa baris akun tes; dicentang -> baris tes tampil dengan badge TEST; login admin verifikasi sementara (dibuat dengan `is_test_account: true`) ikut tersembunyi.
