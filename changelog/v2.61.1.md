# [2.61.1] - 2026-11-03

### ☁️ UAT di Render: Blueprint `render.yaml`, Admin pertama dari env, kunci enkripsi base64 dan 404 yang rapi (Added / Fixed)

- **Permintaan user**: hosting UAT sementara di Render.com. Keputusan: UAT boleh di luar on-premise **hanya dengan data dummy**; produksi tetap SQL Server on-premise. Di Render: SATU Web Service (Express melayani API dan frontend hasil build dari origin yang sama, dibutuhkan cookie `SameSite=Strict` dan cek Origin) + Render PostgreSQL (backend `pg` dari v2.61.0). Tanpa Ollama dan Video Extractor di sana.
- **Masalah**: Render free tidak punya shell dan tidak punya persistent disk, jadi `npm run auth:create-admin` tidak bisa dijalankan dan tidak ada cara membuat Admin pertama; kunci yang dibuat `generateValue` Render berformat base64 sedangkan `secretBox.js` hanya menerima 64 karakter hex (kunci env diabaikan, kunci baru ditulis ke disk sementara dan hilang saat restart). Selama pengujian simulasi ditemukan juga beberapa jawaban yang tidak rapi (lihat "Perbaikan").
- **`render.yaml` baru** (Blueprint, tanpa nilai rahasia):

- **Admin pertama dari env** (`authService.ensureBootstrapAdmin({ store, env, log })`, dipanggil `server.js` setelah storage siap dan sebelum `listen`):
  - Hanya bila `BOOTSTRAP_ADMIN_USERNAME` diisi DAN tidak ada ADMIN **aktif** (Admin nonaktif tidak dihitung): satu ADMIN lewat `storage.createUser`, password = hash scrypt `DEFAULT_INITIAL_PASSWORD`, `must_change_password` true, `is_test_account` false, nama `BOOTSTRAP_ADMIN_NAME` (default "Administrator PX"), e-mail `BOOTSTRAP_ADMIN_EMAIL` (dibuang dengan peringatan bila tidak valid).
  - Audit `USER_CREATE` oleh `system:bootstrap-admin`; password tidak pernah ada di log, audit, maupun respons.
  - Tidak membuat apa pun (peringatan di log) bila password kosong/hanya spasi, username tidak valid (3-50 karakter: huruf, angka, titik, minus, garis bawah), atau username sudah dipakai akun USER/nonaktif - akun itu tidak pernah dinaikkan ke ADMIN atau diaktifkan ulang.
  - Ada Admin aktif -> satu baris log, tidak ada yang dibuat. Error ditulis ke log dan server tetap jalan. Berlaku di `sql`, `pg` dan `json`. Dua boot bersamaan -> satu Admin (kunci unik username); boot lainnya mencatat kegagalan dan tetap jalan.
  - Peringatan boot "belum ada akun" (`warnIfNoUsers`) kini berbahasa Inggris dan menyebut `BOOTSTRAP_ADMIN_USERNAME` + `DEFAULT_INITIAL_PASSWORD` sebagai alternatif tanpa shell.
- **`secretBox.js`**: `SETTINGS_ENCRYPTION_KEY` dari environment boleh juga base64 dari 32 byte (standar atau URL-safe, padding opsional) - format `generateValue` Render. Hex 64 karakter tetap berlaku; nilainya di-`trim` (spasi/baris baru dari dashboard). Nilai yang ada tetapi tidak valid -> satu `console.warn` per proses yang menyebut format yang diharapkan (nilainya tidak pernah dicetak), lalu fallback lama (kunci di `.env`, atau kunci baru; di Render kunci baru itu hilang saat restart). `.env` dan kunci yang dibuat sendiri tetap hex.
- **Perbaikan di `server.js`** (`version` = `2.61.1`):
  - **Fallback SPA**: `index.html` hanya untuk GET/HEAD, tidak untuk `/assets/...` dan path yang berakhiran ekstensi file. Sebelumnya chunk lama `/assets/<hash>.js` setelah redeploy dijawab `index.html` 200; kini 404. Deep link rute klien tetap mendapat aplikasi.
  - Path tak dikenal di bawah `/api`, `/uploads`, `/exports` -> JSON 404 `{"error":"Not found"}` (tanpa login: 401 JSON dari gerbang login), bukan halaman HTML Express.
  - Form publik `POST /api/events/:id/attendance` dan `/feedback` untuk event yang tidak ada -> 404 `Event not found`. Sebelumnya SQL Server/PostgreSQL menjawab 400 dengan teks error foreign key mentah dan JSON store menerima baris absensi yatim.
