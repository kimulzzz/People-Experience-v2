# [2.60.3] - 2026-10-29

### 🧠 AI Summary rapat lebih lengkap: JSON schema per panggilan Gemma & poin penting dilindungi saat merge (Changed / Fixed)

- **Keluhan / permintaan user**: user membandingkan AI Summary video "HR Projects Update…Meeting Recording" dengan notulen manual rapat (internal) yang dipakai sebagai acuan 22 poin yang bisa dicek. Ringkasan live v2.60.1 hanya mencakup **34%** acuan (agenda People Experience 0 dari 7 poin).
- **Penyebab** (spike baca-saja dengan Gemma asli, tanpa menulis ke database):
  1. **JSON rusak di langkah map**: dengan `format: 'json'` Gemma menulis isi yang benar tetapi merusak struktur JSON, lalu berputar sampai `num_predict` habis atau Ollama menghentikannya ("token repeat limit"). Bagian itu dihitung kosong, dan yang hilang justru bagian rapat yang paling padat keputusan.
  2. **Merge membuang isi**: topik hasil map saja jauh lebih lengkap daripada hasil setelah merge; angka, keputusan, dan target "diringkas habis".
- **JSON schema sebagai `format`** (Ollama structured outputs) untuk SETIAP panggilan mode topik: deteksi agenda, pengelompokan agenda, map, single merge, merge agenda/blok (`mediaSummaryService.js`). Builder: `topicSchema(lang, { minTopics, maxTopics, minPoints, maxPoints, withSummary })`, `mapSchema`, `agendaDetectSchema`, `agendaGroupSchema`. Semua field wajib (`required`). Key mengikuti bahasa prompt: id `topik`/`judul`/`poin`/`ringkasan` (deteksi `agenda_baru`/`nama`/`kutipan`, kelompok `agenda`/`nama`/`mulai`); bahasa lain memakai key Inggris (`topics`/`title`/`points`/`summary`, `new_agendas`/`name`/`quote`, `agendas`/`name`/`start`). `parseJsonAnswer`/`normalizeTopics` dan retry dengan `REPEAT_GUARD` tetap ada sebagai lapis kedua. `localAiService.js` hanya mendapat komentar; `format` sudah diteruskan apa adanya sejak v2.60.0.

  | Panggilan | Topik | Poin per topik | `num_predict` |
  | :--- | :--- | :--- | :--- |
  | Map, bagian >= 2.000 karakter (`TOPIC_SHORT_PART_CHARS`) | 2-4 (prompt: "2 sampai 4 topik") | 2-3 | 700 (dulu 500) |
  | Map, bagian < 2.000 karakter (ekor transkrip) | 1-3 | 1-3 | 700 |
  | Single merge | min(4, topik map)-8 + `ringkasan` | 1-4 | 1400 (tetap) |
  | Merge agenda | min(2, topik masukan)-5 + `ringkasan` | 1-4 (dulu 1-3) | 1300 (`GROUP_MERGE_PREDICT`, dulu 900) |
  | Merge blok | min(2, topik masukan)-4 + `ringkasan` | 1-4 (dulu 1-3) | 1300 |
  | Deteksi / pengelompokan agenda | bentuk saja, tanpa batas jumlah | - | 250 / 200 (tetap) |

  `TOPIC_PART_LIMITS` kini 4 topik x 3 poin (dulu 3 x 3). Kalimat prompt map tentang poin tetap "1 sampai 3 poin"; minimal 2 poin untuk bagian panjang dipaksa oleh skema.
- **Langkah protect** (`protectPoints`, `isProtectedPoint`), setelah setiap merge, tanpa panggilan Gemma tambahan:
  - **Poin yang dilindungi**: poin map (sudah lolos cek fakta di langkah map) yang memuat angka, nama bulan (id/en, tanpa "may"), atau kata keputusan/target/progres (id + en, mis. setuju, disepakati, target, tindak lanjut, selesai, minggu depan, agreed, approved, decided, follow-up, next week).
  - **Dikembalikan bila** kurang dari `PROTECT_KEEP` (60%) prefiks katanya (6 huruf pertama kata >= 4 huruf) ada di hasil, ATAU salah satu angkanya tidak ada di hasil.
  - **Ke mana**: ke topik akhir yang paling mirip selama topik itu punya kurang dari `PROTECT_TOPIC_POINTS` (5) poin; selain itu sebagai topik sendiri dengan judul map (judul dicek, urut bagian rekaman) hanya bila jumlah topik masih di bawah cap (single merge 8, agenda 6, blok 5).
  - Poin dicek ulang (`isFillerPoint`, `fragmentProblem`): yang ditolak cek fakta tidak pernah dikembalikan.
  - Urutan pada merge agenda/blok: `restoreCoverage` -> protect -> `removeDuplicatePoints`; pada single merge: protect -> `removeDuplicatePoints`.
  - Statistik baru `protected_points` di `summary_topic_stats` (kini 19 field).
- **`isDuplicatePoint`**: dua poin dengan angka berbeda (atau satu berangka, satu tidak) tidak pernah dianggap duplikat, jadi angka yang dikembalikan protect tidak dibuang lagi.
- **Perbaikan ringkasan**:
  - "Agenda ini / Bagian ini / Potongan ini membahas ..." dan "This agenda / section ..." kini juga diganti pembuka netral.
  - Pembuka netral PERTAMA yang berbunyi "Pembahasan juga mencakup" / "The discussion also covers" kehilangan "juga"/"also"; pembuka berikutnya tetap "juga"/"also".
  - Ringkasan grup (agenda/blok) yang gagal tetap dibuang dan diganti satu kalimat dari judul topiknya sendiri, ringkasan grup lain tetap dipakai (perilaku v2.60.1, kini juga dites untuk merge blok).
