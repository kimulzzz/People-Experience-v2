# [2.57.0] - 2026-10-23

### 📝 Menu Summary Questions: pertanyaan template ringkasan diatur Admin (Added / Changed)

- **Permintaan user**: tambah menu untuk mengubah pertanyaan, sehingga bila pertanyaan survei yang templatenya diunggah berubah, cukup diatur di menu itu; hanya Admin yang boleh mengatur.
- **Masalah sebelumnya (v2.55.0)**: kolom pertanyaan file ringkasan metrik 5, 7, 12 dibaca apa adanya dari header file, tanpa daftar pertanyaan yang ditetapkan; template unduhan memakai header upload terakhir / template seed, dan pergantian pertanyaan tidak terdeteksi maupun tercatat.
- **UI**: Admin Parameters -> tab baru **Summary Questions** (setelah Directorates, ikon `ListOrdered`; `src/components/PartQuestionsManager.jsx`). Dropdown **Template** per metrik/bagian (5; 7 x 4 bagian; 12; 19; 20); per pertanyaan: teks, tipe ("Scale (1-5)" atau "Scale (0-100%)" sesuai skala bagian, atau "Text answer (not scored)"), Move up/down, hapus; **Add Question**, **Save Questions**, **Discard**. Menampilkan upload terakhir dan apakah pertanyaannya berbeda dari konfigurasi. Metrik 12: pertanyaan = pertanyaan **satu blok event** (nama event diambil dari file, "Events in the latest file: ..."); metrik 19/20: "This template has no question columns (a combined score table) - there is nothing to configure."
- **Data**: kolom baru `px_metric_parts.questions_json NVARCHAR(MAX) NULL` (ALTER idempoten `COL_LENGTH`; jumlah tabel tetap 41), JSON `store.json` `metricParts[].questions`; isi `[{ key, text, type }]` urut kolom, `type` `SCALE`|`TEXT`. `NULL` = belum dikonfigurasi -> perilaku v2.55.0 (kolom file dibaca apa adanya, tanpa cek jumlah). Snapshot per upload di `px_metric_part_uploads.columns_json.questions_snapshot` (`question_labels` tetap = header file). Logika bersama: `server/db/partQuestions.js` (baru).
- **Boot `topUpPartQuestions()`** (SQL; JSON `topUpStorePartQuestions()` saat `store.json` dimuat): hanya bagian dengan `questions` `NULL`, sekali: header upload terakhir > template seed > kosong. Tipe `TEXT` bila seed `question_types` menyatakannya atau baris tersimpan upload itu hanya berisi teks untuk kolom tersebut; selainnya `SCALE`; kunci `q1`, `q2`, ... Seed Onboarding Survey Day 1 kini = 3 pertanyaan file saat ini, `question_types` `[SCALE, TEXT, SCALE]`.
- **Endpoint (Admin saja; USER 403, tanpa login 401)**:

  | Endpoint | Respons / aturan |
  | :--- | :--- |
  | `GET /api/admin/part-questions` | `{ metrics: [{ metric_id, metric_name, parts: [{ part_key, part_name, sort_order, scale, kind, configured, questions, event_labels, uploads_count, latest_upload: { upload_id, file_name, uploaded_at, question_texts }, differs_from_latest_upload }] }], question_types, max_text, max_questions }`; `kind` = `QUESTIONS` \| `EVENT_BLOCKS` (metrik 12) \| `SCORE_TABLE` (19/20) |
  | `PUT /api/admin/part-questions/:metric_id/:part_key` | Body `{ questions: [{ key?, text, type? }] }` mengganti seluruh daftar; `type` default `SCALE`; kunci baru otomatis `q<n>`. 400: bukan list, teks kosong / > 500 karakter, tipe salah, kunci kembar / format salah, > 60 pertanyaan, bagian `SCORE_TABLE`; 404: bagian tidak dikenal / metrik tanpa bagian; id bukan angka 400. Audit `PART_QUESTIONS_UPDATE` (mis. "metric 7 DAY1_SURVEY: 2 -> 3 questions; added q3; text q2,q1; reordered") |

  `GET /api/admin/metric-parts/:metric_id` kini juga mengirim `kind` dan `questions` per bagian.
- **Template**: kolom pertanyaan = teks terkonfigurasi berurutan; metrik 12: per event, nama event (dari upload terakhir / template) + pertanyaan terkonfigurasi.
- **Upload**: kolom pertanyaan (setelah skor di kolom E) dipetakan **berdasarkan posisi**; label tersimpan = teks terkonfigurasi, `file_label` = header file, plus `key` dan `type`. Jumlah beda -> 400 "The file has N question columns (after the score in column E), the configured template has M questions - update the questions in Admin Parameters -> Summary Questions or use the latest template.", tidak ada yang tersimpan. Metrik 12: jumlah kolom harus kelipatan blok (1 + jumlah pertanyaan), header event biru harus di awal setiap blok. Kolom `SCALE` harus angka pada skala bagian atau "-" (teks -> 400 yang menyarankan mengubah tipe ke Text di menu); kolom `TEXT` disimpan sebagai teks, tidak pernah dinilai. Skor tetap dari kolom E (tidak berubah).
- **History / Evidence**: baris tetap memakai teks pertanyaan saat upload. Set pertanyaan diberi nomor Set 1, Set 2, ... menurut urutan upload. Satu set dalam periode = tata letak lebar seperti sebelumnya; beberapa set = satu baris per baris data dan pertanyaan (`Question_Set | Question_No | Question | File_Header | Value`; metrik 12: tata letak panjang + `Question_Set`). Respons History mendapat `notes` -> banner amber "Question set changed: ..." di `MetricHistoryTable.jsx`.
- **Config guard**: `px_metric_parts` masuk `CONFIG_TABLES` (JSON `CONFIG_KEYS` `metricParts`), jadi pertanyaan yang diatur Admin dipulihkan setelah suite (menutup catatan terbuka v2.55.0).
