# [2.61.0] - 2026-11-03

### 🗄️ Backend ketiga PostgreSQL (`STORAGE_BACKEND=pg`) untuk UAT, satu kode storage untuk SQL Server dan PostgreSQL lewat lapisan dialek (Added)

- **Permintaan user** (2026-11-03): dua versi database - **SQL Server** untuk deploy PRODUKSI on-premise nanti, **PostgreSQL** untuk hosting UAT sementara di Render.com. User memilih SATU jalur kode dengan lapisan dialek (bukan `pgStorage.js` terpisah), supaya fitur cukup ditulis sekali.
- **Konteks kepatuhan** (diputuskan minggu yang sama): aturan 100% on-premise berlaku untuk PRODUKSI. UAT boleh di luar on-premise, tetapi **hanya dengan data dummy/seed** (tanpa baris Exit Interview asli, file ESS asli, atau akun asli). Deploy ke Render sendiri (`render.yaml` dll.) adalah langkah BERIKUTNYA, bukan bagian 2.61.0.
- **Backend baru** (`server/db/storage.js`): `STORAGE_BACKEND=pg` di samping `sql` (on-premise) dan `json` (default bila kosong; nilai lain juga jatuh ke `json`). `sql` dan `pg` sama-sama memakai `sqlStorage.js`; dialeknya dipilih `server/db/dialects/index.js`.
- **Koneksi PostgreSQL** (`server/db/dialects/pg.js`, dependensi npm `pg` ^8.23.1):

  | Variabel | Arti |
  | :--- | :--- |
  | `DATABASE_URL` | Connection string (Render). Bila diisi, `PG_HOST`..`PG_DATABASE` diabaikan |
  | `PG_HOST` / `PG_PORT` / `PG_USER` / `PG_PASSWORD` / `PG_DATABASE` | Tanpa `DATABASE_URL`; default `localhost` / `5432` / - / - / `peopleexperiencepx` |
  | `PG_SSL=1` | TLS tanpa pemeriksaan sertifikat (`rejectUnauthorized: false`), untuk URL EXTERNAL Render. Jangan menambah `?sslmode=require` ke `DATABASE_URL`: itu mengalahkan `PG_SSL` dan `pg` 8 lalu memverifikasi sertifikat penuh |
  | `PG_POOL_MAX` | Ukuran pool (default 10) |

  Sesi memakai zona waktu UTC (`-c TimeZone=UTC`), `statement_timeout` 120 dtk.
- **Lapisan dialek** `server/db/dialects/` (`index.js`, `mssql.js`, `pg.js`), kontrak yang sama:
  - query runner: SQL tetap ditulis sekali dengan parameter `@name`; `pg.js` mengubahnya menjadi `$n` dengan tokenizer (string, identifier berkutip, dan komentar tidak disentuh; nama yang sama = nomor yang sama), bukan regex atas seluruh teks;
  - transaksi (`inTransaction`), pengenal unique violation/deadlock;
  - `upsert`: `MERGE` di SQL Server, `INSERT ... ON CONFLICT ... DO UPDATE` di PostgreSQL. Opsi `holdlock` (default mati) hanya dipakai `saveExitInterviewUpload` dan `saveSocialMediaStats`, persis di tempat hint itu ada sebelumnya;
  - `rowCount()`: SQL Server menjalankan statement + `SELECT @@ROWCOUNT` dalam satu batch, sehingga hitungan benar juga bila server berjalan dengan `SET NOCOUNT ON`; PostgreSQL memakai row count-nya sendiri;
  - insert dengan id eksplisit, bulk insert, cek katalog (tabel/kolom ada), I/O snapshot konfigurasi;
  - fragmen SQL: top/limit, now, `dateStr`, year/month, `bin` (perbandingan persis), TRUE/FALSE, OUTPUT vs RETURNING, lock hint (PostgreSQL: `LOCK TABLE ... SHARE ROW EXCLUSIVE` pada transaksi).
- **Skema PostgreSQL** `server/db/schema.pg.sql`: **41 tabel** yang sama (schema `dbo`, idempoten, satu transaksi implisit):
  - semua kolom teks `CITEXT`, sehingga pencarian dan kunci UNIQUE tidak membedakan huruf besar/kecil seperti collation default SQL Server; perbandingan persis lewat `bin()`;
  - kunci UNIQUE dengan kolom nullable memakai `NULLS NOT DISTINCT` (`uq_px_ess_results`, `uq_px_user_scopes`) -> butuh **PostgreSQL 15+**, dicek saat `applySchema` dengan pesan jelas;
  - ekstensi `citext` dibuat oleh skema (`CREATE EXTENSION IF NOT EXISTS citext`), jadi role database harus boleh membuatnya;
  - BIT -> BOOLEAN, DATETIME2 -> TIMESTAMPTZ(3) (UTC), identity -> `GENERATED BY DEFAULT AS IDENTITY`.
- **Tipe data sama dengan driver `mssql`**: BIGINT/COUNT(*) dan NUMERIC sebagai number, DATE sebagai `Date` UTC tengah malam (tanpa geser hari), BOOLEAN sebagai boolean. Sequence identity disinkronkan setelah import/restore dan saat boot (`syncIdentities`), tidak pernah dimundurkan (id yang pernah dipakai tidak dipakai ulang).
- **`sqlStorage.js`**: konstruksi khusus SQL Server ditulis ulang agar jalan di kedua dialek (tabel temp, `DECLARE`/`IF`, `UPDATE ... FROM`, `DELETE alias FROM`, batch multi-statement, `@@ROWCOUNT`, `ISNULL` -> `COALESCE`). Perilaku SQL Server tidak berubah (bukti di bawah).
- **Skrip**: `migrate.js` (termasuk `--reset`; tanpa `--reset` menolak database yang sudah berisi data), `exportToJson.js` (`npm run db:export`) dan `npm run auth:create-admin` jalan di PostgreSQL. Database PostgreSQL kosong + boot pertama = seed demo yang sama dengan SQL Server; boot kedua idempoten.

- **Catatan / batasan**:
  - Temuan lama di kedua backend, TIDAK diperbaiki: cek cakupan USER membedakan huruf (`?directorate=business banking` -> 403); importer CSV menerima divisi yang tidak ada di direktori.
  - PostgreSQL: `CITEXT` tidak menegakkan batas panjang kolom SQL Server; spasi di akhir teks ikut dibandingkan; urutan teks non-ASCII bisa berbeda (tidak ada logika aplikasi yang bergantung padanya).
  - Belum diuji: `SEED_DEMO_DATA=false` di PostgreSQL, tulis bersamaan di bawah lock tabel PostgreSQL, Render itu sendiri (`DATABASE_URL` + `PG_SSL`, izin membuat `citext`).
  - Untuk deploy Render nanti: PostgreSQL 15+ dengan `citext`; aturan SSL di atas; set `SETTINGS_ENCRYPTION_KEY` sebagai env var Render (kalau tidak, kunci baru ditulis ke disk sementara dan password e-mail tersimpan tidak terbaca setelah redeploy); upload (`server/uploads`, `server/data/*-uploads`) hilang saat redeploy tanpa persistent disk (baris DB tetap); tidak ada Ollama/Video Extractor (transkrip tidak tersedia, AI Summary jatuh ke rule-based); admin pertama lewat `npm run auth:create-admin` dengan env PostgreSQL atau `DEFAULT_INITIAL_PASSWORD`; data dummy saja.
