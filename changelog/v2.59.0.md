# [2.59.0] - 2026-10-23

### 📦 Batas ukuran unggahan foto/video Signature Program Events diatur Admin (Added / Changed)

- **Permintaan user**: naikkan batas ukuran unggahan foto/video di Signature Program Events. Keputusan user: **1 GB**, diatur sebagai setting Admin di Admin Parameters.
- **Sebelumnya**: batas tetap dari env `MEDIA_MAX_MB` (default 200 MB); mengubahnya butuh edit `.env` + restart backend.
- **Backend**:
  - Setting baru `px_app_settings.media_upload_max_mb` (MB per file, bilangan bulat 1-4096, default 1024; seed `initialAppSettings.media_upload_max_mb`). Saat boot ditambahkan bila belum ada di kedua backend (top-up `initialAppSettings` yang sudah ada), tidak pernah menimpa nilai tersimpan. Dibaca lewat `GET /api/settings`.
  - `PUT /api/admin/settings/media_upload_max_mb` `{ value }`: Admin saja (USER 403, tanpa sesi 401); nilai tidak valid -> 400 "Max photo/video upload size (MB) must be a whole number between 1 and 4096."; audit `SETTINGS_CHANGE` `media_upload_max_mb: <lama> -> <baru>`.
  - `POST /api/events/:id/media` membaca batas per request (`getMediaMaxMb()`, cache 30 dtk yang dikosongkan saat setting disimpan; satu instance multer per nilai batas via `mediaUploaderFor(mb)`) -> perubahan berlaku pada unggahan berikutnya tanpa restart. Melebihi batas -> 413 `{ error: "The file exceeds the 1024 MB (1 GB) limit.", max_mb }`; file yang terpotong tidak tertinggal di `server/uploads/`.
  - Sumber kebenaran = setting DB. Env `MEDIA_MAX_MB` kini hanya fallback bila setting tidak bisa dibaca/tidak valid (bila env juga kosong/tidak valid: 1024).
  - Allowlist MIME + ekstensi (v2.30.1), rename nama asli, transkrip dan AI Summary tidak berubah.
- **Frontend**:
  - Admin Parameters -> Journey Parameters -> kartu baru **Upload Limits** di bawah PX Index Weights (`UploadLimitCard` di `AdminParametersModal.jsx`; helper baru `src/utils/mediaLimit.js`: `MEDIA_MAX_MB_RANGE`, `mediaLimitLabel`): field "Max photo/video upload size (MB)" (1-4096), pratinjau "= 1024 MB (1 GB) per file", catatan amber "Videos longer than ~2 hours may exceed the 120-minute transcript limit.", tombol **Save Limit** (aktif bila valid dan berubah).
  - Signature Program Events (`EventManager.jsx`): teks "Max 1024 MB (1 GB) per file" di samping **Upload Photo / Video**; file yang lebih besar ditolak di browser sebelum dikirim (alert dengan ukuran file). Batas dibaca sekali saat halaman dibuka; server tetap memeriksa.
- **Proxy / timeout**: batas `express.json` tidak berlaku untuk multipart; `REQUEST_TIMEOUT_MS` backend (120 mnt) sudah cukup untuk unggahan panjang. Server dev/preview Vite masih memakai timeout request bawaan Node (5 mnt) -> plugin baru `px-long-uploads` di `vite.config.mjs` menyetel `requestTimeout` = `REQUEST_TIMEOUT_MS` (developer: terverifikasi 7200000; unggahan uji 300 MB lewat proxy Vite -> 201).
- **Data live**: `media_upload_max_mb` = 1024; setting lain tidak berubah (idle 120 mnt, bobot 70/30).
- **Tes**: Modul 64 (6 tes). Suite penuh SQL (developer): **482/482 lulus, 0 gagal, 7 dilewati** - modul media 27, 32, 38, 41, 42, 43 **dijalankan**, hanya modul event 8/24 dilewati. Ukuran suite **489** menurut hitungan (483 + 6). Suite JSON penuh tidak dijalankan.
- **Insiden saat pengembangan**: cek JSON in-process developer menulis ulang `server/data/store.json` (escape regex hilang); dipulihkan byte-identik dari backup. `store.json` tidak dipakai pada backend SQL dan tidak di-commit.
- **Browser**: dicek main session di :5000 (v2.59.0): `GET /api/settings` -> `media_upload_max_mb` 1024; Signature Program Events menampilkan "Max 1024 MB (1 GB) per file"; Admin Parameters -> Journey Parameters menampilkan kartu "Upload Limits" (isian 1024, "= 1024 MB (1 GB) per file", catatan batas transkrip 120 menit, tombol Save Limit) di bawah PX Index Weights
- **Catatan / batasan**:
  - Produksi: reverse proxy HTTPS (IIS/nginx) di depan aplikasi juga harus mengizinkan body >= batas (mis. `client_max_body_size` nginx, `maxAllowedContentLength` IIS) dan timeout panjang - tidak diatur aplikasi.
  - Tidak ada cek ruang disk kosong; file masuk ke `server/uploads/` di mesin server.
  - Video > ~2 jam bisa melewati batas transkrip 120 menit (`TRANSCRIBE_TIMEOUT_MS`) walau lolos batas ukuran.
  - Halaman Events yang sudah terbuka memakai batas lama sampai dimuat ulang (server tetap menegakkan batas baru).
