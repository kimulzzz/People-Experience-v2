# [2.54.1] - 2026-10-21

### 📈 Rumus skor bertingkat diubah ke interpolasi antar batas (Changed)

- **Masalah (temuan QC v2.54.0)**: rumus v2.54.0 "nilai ÷ batas bawah tier × nomor tier" tidak monoton - nilai lebih tinggi bisa mendapat skor lebih rendah tepat setelah melewati batas tier. Contoh metrik 1: 2,00% -> 80%, tetapi 2,01% -> 60,3%.
- **Keputusan user**: ubah menjadi **interpolasi antar batas** (skor naik terus seiring nilai). Rumus baru (`server/db/scoreTiers.js` `tieredScore` dan salinannya `src/utils/scoreTiers.js` untuk pratinjau Admin):
  - tier 1 (di bawah batas tier 2): skor = nilai ÷ batas tier 2 (0-1) - sama seperti sebelumnya;
  - tier t = 2, 3, 4: skor = t + (nilai - batas bawah tier t) ÷ (batas tier t+1 - batas bawah tier t) (naik lurus dari t ke t+1);
  - tier 5: skor = 5 (= 100%);
  - Skor % = skor ÷ 5 × 100, dibatasi 0-100. Operator `>=` / `>` per batas tetap menentukan tier.
- **Dampak data live**: nilai metrik yang ada **tidak berubah** - metrik 14 6400 orang = 4 + 400/1500 = 4,27 = **85,33%**; metrik 1 0,66% = **13,2%**; metrik 3 75,04% = **100%**. Target: metrik 14 5000 = 60% (tetap), metrik 3 70% = 93,33% (tetap), **metrik 1 2% = 60%** (sebelumnya 80%; 2% adalah batas atas tier 2 karena batasnya `>`). Threshold metrik 1 (20%) dan 14 (40%) tetap; PX Index tidak berubah. `tier_info.capped` kini hanya `true` bila skor dibatasi di 0..5 (tier 5 tidak lagi "capped").
- **UI**: teks penjelasan rumus di Admin Parameters (Score Tiers) dan di detail metrik diperbarui.
- **Tes**: harapan Modul 56 disesuaikan (titik batas, target metrik 1 = 60%, `capped`) + pemeriksaan baru bahwa skor monoton untuk batas metrik 1, 3 dan 14 (401 titik masing-masing). `npx vite build` lulus; suite penuh SQL sebelum commit (modul media/event di-skip): **348/348 lulus, 0 gagal, 16 tes dilewati**. Dicek di :5000 setelah suite: metrik 1 13,2% (target 60%), 3 100%, 14 85,33%, 2 N/A; PX Index YTD 2026 tetap **81,48** (Survey 87,47, Outcome 67,49).
